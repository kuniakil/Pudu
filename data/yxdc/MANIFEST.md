## 3. ⭐ 已知问题：两版小节数对不上（**下一步必须先解决**）

两个来源的**印刷小节号**（系统起始小节号）：

| | 五线谱（staff） | 简谱（jianpu） |
|---|---|---|
| 每系统小节数 | 3 | 4 |
| P1 | 1, 4, 7, 10, 13 | 1, 5, 9, 13, 17, 21 |
| P2 | 16, 19, 22, 25, 28 | 25, 29, 33, 37, 41, 45, 49 |
| P3 | 31, 34, 37, 40, 43 | 53, 57, 61, 65, 69, 73, 76 |
| P4 | 46, 49, 52, 55, 58 | — |
| P5 | 61, 64, 67, 70, 74 | — |
| **推得总小节** | **78** | **79** |

**对齐点**：1 / 13 / 25 / 61 两边都吻合。
**分歧点**：从 61 之后开始漂移 —— staff 是 64, 67, 70, 74，jianpu 是 65, 69, 73, 76。

### 可能原因（待验证）

1. **两个版本来源不同**：everyonepiano 的五线谱 PDF 与简谱 PNG 可能分别来自不同制谱，
   中间某处多/少一个小节（例如某小节在其中一个版本被拆成两小节）。
2. **staff 版在 70–73 处有 4 小节的系统**（其余系统一律 3 小节），是分页造成的不整齐，
   音乐本身没问题，只是小节编号的推进和简谱不一致。

### 为什么要紧

逐小节比对的正确姿势是「**按印刷小节号对齐**」，而不是「按第 N 个小节对齐」。
现在两边的编号只在 1/13/25/61 对得上，之后错位，所以：

- 如果**不**先解决，做出来的「逐小节比对」会从第 62 小节起整体错位，
  报告出来的「音符错」很可能全是**假阳性**。
- 解决方式：跑 OMR 让 Audiveris 报出权威的小节数与每小节内容，
  再和简谱侧的印刷编号对齐，**定位到具体是哪一个小节多/少**。

> **这是下一步的第一个待办**，写进了
> `docs/JIANPU-CONVERSION-NOTES.md` §9 行动清单。

## 4. 下次接手怎么用

```bash
# 0. 语料已就位（若目录为空则重建）
bash tools/fetch_ground_truth.sh

# 1. OMR：五线谱图 → MusicXML（需要先装 Audiveris，见 docs/REFERENCES.md §5）
python3 tools/quickstart.py data/yxdc/yxdc-staff-1.png --out /tmp/yxdc_out
#    Audiveris 会报出「第几页 / 多少小节 / 多少音符」→ 与本文件 §3 对照

# 2. 转简谱：MusicXML → Pudu L2 → HTML/PNG/PDF
#    （quickstart.py 已含这一步）

# 3. 比对：把 Pudu 产物与 yxdc-jianpu-*.png 并排，逐小节人工核对
```

**比对时要记录的三类问题**（`docs/JIANPU-CONVERSION-NOTES.md` §3 已定义）：

| 类别 | 症状 | 归属 |
|---|---|---|
| A. 音符错 | 音高 / 时值 / 小节数不对 | **算法层**（真问题） |
| B. 排版丑 | 音符对，但断行、下划线、八度点位置难看 | **渲染层**（换渲染器可解） |
| C. 缺件 | 装饰音 / 三连音 / 反复记号 / 力度 / 踏板 | **覆盖度**（按需补） |

> 目前**尚未证明 A 类问题存在**。第一轮比对的目的是确认这一点。

## 5. 图片水印（可能干扰 OMR）

五线谱与简谱图上都印着对角线 **"EOP"** 水印，以及 `Everyone Piano` 页眉页脚。
这些灰度水印横跨谱面，**可能干扰 Audiveris 的符头/符干检测**。

若 OMR 结果不佳，优先尝试：

1. 提高对比度 + 二值化（去掉浅灰水印）；
2. 裁掉页眉页脚（保留谱面区域）；
3. 分系统裁切后再喂（每张图谱面更干净，Audiveris 对单系统识别率更高）。

这一步尚未做实验，先记在案上。
